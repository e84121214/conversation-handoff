# 連續性與涵蓋界線

## 尋找基準

優先讀使用者提供或指定的交接目錄，再找當前專案既有 handoffs、進度紀錄與相關對話。先以檔名／索引縮小範圍，再讀候選內容，不掃描所有私人資料夾。沒有工具時，請使用者提供上一份交接，不假裝有跨機持久記憶。上次完整交接與最新工作狀態可能是不同檔案，兩者都要核對。

以 project_key（穩定的專案名稱或 repo 識別，不能單靠機器絕對路徑）、目標、工作主線與來源判定相關性。以事件截止點及明確前後關係判斷新舊，檔案修改時間只用來找候選。生成較晚但涵蓋較早事件的摘要不會自動成為較新進度。

把工作紀錄讀到各模式上次涵蓋界線，首次讀到可取得的工作起點；不因工具預設只回傳最近幾則就停止。若有截斷或無法存取，記錄實際覆蓋範圍並保留缺口。混有不同專案時分開交接，不把其結果合併。

## 差異與合併

舊版若只有單一 Markdown 而沒有 manifest，仍讀取其中已知的目標、狀態與期間作基準，註記「由舊版交接遷移」。未知的模式界線保持 null，不推定已成功輸出實驗結果；首次新版輸出重新核對可見事件，標明可能與舊檔重疊的部分，不丟棄尚未確認已涵蓋的事件。

比較以下實體：研究問題、需求／限制、實驗設定、run、指標、文獻決策、待辦與成果。沿用可辨識的實驗、run、決策及待辦 ID；新 ID 保持穩定且不得重複利用。以來源事件／檔案／設定辨識重複資料，不只比數字或名稱。同一 run 的更正記修訂關係，重跑則是新 run。

保留前次有效事項，逐項判定新增、改變、完成、失效、未變或衝突。明確新更正可取代舊結論，但保留原說法、理由及更正時點於本次脈絡。沒有證據時不得把助理建議升格為使用者決策。衝突無法判定時並列來源，問最小必要問題，不自行消除。

輸入比當地舊：保留當地較新進度並列輸入提供的獨有背景。兩條分支各有新工作：合併相容項，保留分歧。當地無歷史：以輸入為基準，標示本機未核實。每次匯入產生新合併狀態，不能推進任何匯出模式的涵蓋界線。

## manifest.json

用可讀的 JSON 記錄必要元資料，不包含憑證與研究數據原文。以下為欄位約定，值依實際資料填入，不照抄虛構值：

- `schema_version`：目前為 2。
- `handoff_id`、`project_key`、`workstream`、`operation`（export/import）、`created_at`（ISO 8601 含時區）。
- `parents`：直接比較／合併來源的 ID、相對位置或可用連結；無基準則空陣列。
- `coverage`：本次截止點、來源對話 ID／檔案與已讀事件範圍、缺口、確認休息日期及無紀錄日期。來源時間未知時填 null 並說明，不用檔案生成時間冒充事件時間。
- `mode_checkpoints`：`context`、`results` 各自保存最近成功匯出的 handoff ID、已涵蓋來源事件範圍／游標及截止點。未輸出模式保留前值，首次無前值為 null。時間戳不足以防重複時使用事件 ID 與來源識別；遲到的舊事件若尚未涵蓋仍需補入。
- `artifacts`：本次檔名、用途、模式、狀態（complete/partial/unavailable）。
- `dependencies`：必要輸入與歷史成果的相對路徑／連結、搬移狀態與缺少原因。

不要把特定本機的 latest 指標當成唯一真相。目錄內含 manifest 與自足 state，攜帶到新機即可重新辨識；有多候選版本時追溯 parents，不能僅依檔名取最大值。

先保存報告、核對成功，再完成 manifest 的成功界線。失敗不前移界線；重試讀取已完成產物並避免重複記錄。更換模式時只更新成功模式。沒有新事件可產生標示「無新增」的快照，但不捏造工作。

## 期間判定範例

- 週一至週三工作，週四確認休息，週五至週六繼續。首次在週三匯出：涵蓋週一至週三；再於週六匯出相同模式：新增週四至週六，註明週四休息，並在 state 保留前段必要現況。
- 一直到週六才首次匯出：涵蓋週一至週六全部工作與週四休息。休息日不切斷期間，也不把一週當固定視窗。
- 週三只匯出脈絡，週六匯出全部：脈絡接續週三之後；結果仍涵蓋週一至週六尚未匯出的結果。
- 只有週三和週五紀錄，未說明週四活動：標記週四無可見紀錄，不稱休息。
- 使用者例子先說週四休息、後括號誤稱週三：說明採用前述週四，勿據此創造兩天休息。
